## 5. Camera till — full-till design, de-risked in three cuts

You chose the full till (ring up each sale). Ship it as three cuts so the till earns trust before it carries the sale:

- **Cut 1 — stock-book scan (week 1–2 value).** WhatsApp/iMessage photo of the paper book → PaddleOCR sidecar (reuse `documents/extraction/ocr.py` pattern, new merchant pipeline) → line-item parse (item, qty, price, date) → human confirm in chat ("I read 42 lines, 3 unclear — tap to fix") → opens the ledger history. Success metric: months of history loaded + accuracy %, per the doc's step 2. This is also the fallback for everything below.
- **Cut 2 — payment-confirm per sale (the wedge).** Till generates a one-time account number (or dynamic reference) per sale; buyer pays; partner webhook confirms; Miriam replies "₦X landed — release the goods." Kills fake-transfer alerts on day one and is chargeable from day one (flat fee). Needs §7 per-sale references.
- **Cut 3 — assisted ring-up (the full till).** Camera suggests the SKU (distributor-route catalog first: branded FMCG with stable packaging, barcode-first where printable, vision-assist + one-tap confirm), quantities default from purchase history, price from the pooled book with street-range shown; loose/unbranded goods fall back to quick-pick price list + voice ("2 baskets tomatoes ₦3k"). Never pure auto-recognition for money: every sale is confirmed before it posts — vision proposes, the trader disposes. Shelf-count mode weekly ("point along the shelf") feeds stock-out prediction.

Vision stack: on-device nothing (cheap Androids can't run it); server-side multimodal model for book/shelf parsing + SKU match against the route catalog; barcode decode library for printed codes; all money math stays in deterministic code. Eval: photo-bench per market (branded hit-rate, loose-goods fallback rate, book-line accuracy) before claiming till readiness.

Researched against LangChain 1.0 / LangGraph 1.0 (stable since Oct 2025, ~90M monthly downloads — the "breaks every quarter" objection has expired) plus the release behind your X link: **Managed Deep Agents 0.8 (24 Sep 2026)** adds HTTP channels (agents callable from any webhook — the demo is literally an expense agent living in text messages backed by **Photon, our messaging provider**), user/agent-scoped memory, and per-caller credentials. The shape validates our architecture: webhook in → durable agent run → reply through our own transport. But it does not change the verdict below.

**Verdict: keep our hot path custom; use self-hosted LangGraph for two offline graphs; evaluate with self-hosted tooling; copy LangChain's middleware/memory/eval patterns into our layers.**

1. **Keep:** custom FastAPI Hands→Judgment→Hands→Voice loop, deterministic Python money planner, Go ledger, Concentrate gateway. LangChain's provider abstraction adds nothing over Concentrate; a graph runtime on the hot WhatsApp path adds latency, ~150–250MB/process overhead claims, and per-turn token multiplication (router + workers + synthesizer + evaluator) against airtime-scale ARPU. Anthropic's canonical doctrine agrees: single LLM call → workflow → agent, complexity only with measured gains; Google ADK's structure (deterministic graph, LLM nodes only where judgment is needed) is the shape our money path already follows.
2. **Wrap narrowly — LangGraph library (MIT, our Postgres, `PostgresSaver` + `durability="sync"`) for exactly two offline graphs:** (a) camera ingestion pipeline — ingest→classify→extract→validate→flag as explicit nodes with retries, time-travel debugging, per-node observability; (b) lender-referral pack assembler — orchestrator-worker fan-out (gather history, score, assemble) with an evaluator gate before referral. Background jobs only: no WhatsApp latency pressure, crash-resume genuinely valuable, auditability a lender requirement. `interrupt_before` (never `interrupt_after` — documented footgun) on the referral-send node; `thread_id = merchant_id + workflow_instance` (never bare merchant — cross-shop state bleed is the scariest bug class); lean state (IDs + deltas, artifacts by reference — one team hit 180KB/step checkpoints + 400ms writes); recursion caps; SLA timers + escalation owned by Go (LangGraph ships no timeouts — a WhatsApp approval gap is hours-long by nature).
3. **Do not adopt LangSmith for production observability.** Eval tooling is best-in-class but trace billing is structurally hostile to high-volume WhatsApp traffic (Plus $39/seat, overages $2.50/1k base 14-day / $5.00/1k extended 400-day; per-turn instrumentation at our volumes ≈ $1k+/mo and growing linearly; eval runs bill too), no OSS self-host below Enterprise. Instead run the same methodology (datasets + LLM-judge + online production scoring) on **self-hosted Langfuse/OTel** — our OTel pipeline already exists; dual-emit if we ever trial LangSmith. Free-tier dev trial is fine.
4. **Steal five patterns this quarter (highest ROI, near-zero lock-in):** (i) HITL middleware semantics — approve/edit/reject tool calls, `interrupt_before` naming, resume-by-token (maps onto our `confirm_id` discipline); (ii) summarization middleware for long merchant threads; (iii) PII redaction pre-model (NDPR); (iv) in-loop Pydantic `response_format` at every LLM boundary (OCR lines, advice payloads); (v) checkpointer/thread discipline for our own watchers.
5. **Revisit trigger:** genuinely multi-specialist agentic surface (negotiating + underwriting + collections agents coordinating over days with human gates) — then supervisor/swarm prebuilts earn their keep. Today that complexity taxes every merchant turn.

## 15. How top labs build agents users trust with money — 11 tactics adopted

Adopted as build rules (each maps to code in §§5–8, 11, 16):

- **T1 Calculator Boundary:** any reply containing ₦ must have numbers produced or re-checked by a `compute_*` tool in the same turn — block send otherwise. (Our existing "LLM never computes" invariant, now enforced at send time.)
- **T2 Ground-or-Refuse:** three output states only — Verified / Unverified / Needs-proof ("I can't confirm this payment — check your Moniepoint balance; do not release goods yet").

## 16. Trust-critical data pipeline — the structural core (good vs bad data, transactions, invoices, loans)

Trust invariant: **no single untrusted source ever writes to a credit feature or an advice number without a validation gate + cross-source check + confidence label.** A gamed photo, blurry book, fake alert, or misread invoice lands in quarantine or `Reported`-at-best — structurally incapable of becoming a limit.

- **Extraction (OCR + VLM + rules, never Tesseract-only):** capture QA first (blur/glare/perspective/DPI/EXIF/dupe-hash — retake prompt, not confident garbage); OCR pass for pixel-grounded boxes; VLM semantic pass on the raw image with a structured schema; constrained numeric decoding (read, don't infer); panel agreement on money/count values; schema fail-fast; per-field confidence. Planning number: handwritten stock-book money/count fields at **60–75% field accuracy unaided, 80–90% with constraints + good capture** — claims to triangulate, never facts. An 8-digit handwritten total at 90%/char has a ~57% chance of ≥1 wrong digit; VLM hallucination (fluent invented text) is the new failure mode — ground every value to a box.
- **Transactions (five sub-pipelines):** normalise (Mono/bank/SMS/virtual-account → one schema, posted vs value-date, available vs ledger balance); categorise (regex bootstrap → classifier, merchant-overridable, audited); resolve entities (per-shop supplier registry, never cross-shop merge unconfirmed); dedupe (electronic ±10min; paper-vs-electronic ±2 days + human confirm); disambiguate income vs own-transfers/injections (non-revenue by default). Mono: consent lifecycle, settled-only for credit, model Mono-visible share per merchant (cash + OPay/PalmPay hops undercount). **SMS is evidence, never proof** — every SMS credit carries `source: sms_unverified` until matched to cleared credit or delivery record.
- **Reconciliation R1–R5 (the trust gate):** R1 single-payment match (invoice vs cleared credit, exact/±1%, +0–3d → Verified); R2 14-day flow window (book vs cleared inflows within **±15%** → Verified; 15–30% → Reported + case; >30% or inverted → Conflicted, freeze limit inputs); R3 delivery corroboration (book restock vs distributor record ±10%/SKU); R4 no single-source promotion (SMS + photo of one event = one merchant-controlled source class — bank/distributor must be a leg); R5 fake-alert screens on every inbound "sale" (exact single cleared credit + available-balance movement + settled status + hold period >₦100k; pending/memo/value-dated stays Reported max).
- **Anti-gaming:** photo forensics + capture telemetry (resubmission hashes, burst detection, device clustering, photo-of-photo tells); content plausibility (round-number/Benford analysis, FMCG 8–15% margin realism, velocity feasibility); temporal consistency (real shops are spiky — smooth curves and zero stock-outs are fabrication markers); counterparty corroboration (orphan suppliers = gaming markers). Combined into a trust score gating credit features. Verified-share (cleared ÷ book-claimed) is simultaneously the best risk feature and the best gaming detector.
- **Tiers + hedged advice:** `Verified` / `Reported` / `Unverified` / `Conflicted` with full provenance; credit features consume Verified only; advice is interval-form ("verified ₦150–180k + ~₦40k reported, unconfirmed") — never blended point estimates; weakest-link confidence with disagreement penalty.
- **Loans (referral, honest + predictive):** predictive features are sell-through velocity, stock-out pattern, cash-flow stability (CV, not level), verified-share, supplier-payment regularity, draw discipline, tenure/density — never self-reported income, single photos, SMS-only sales, or anything the merchant can move without moving money. Start-ticket ≤ min(7-day verified sell-through of requested SKUs, 20–30% of 30-day verified inflows); step-up +30–50% on time, freeze/step-down on miss; vintage back-test required before any limit increase (no back-test, no growth — the anti-Alerzo gate; Alerzo/Capiter/MaxAB-Wasoko/Chari are required lender-pitch reading); kill rules (verified-share −20pts, two broken R2 windows, unverified spike → auto-freeze + notify). Collections: supply-closed loop first ("no pay, no restock"), settlement intercept second, graduation consequences third. First-loss 5–15% per vintage + DFI partial-guarantee fit (AGF/IFC-style, women/climate windows) + vintage caps.
- **Eval + monitoring from day one:** Golden-Doc-200 (stratified pages, accountant truth, money fields 5× weight, 0% hallucinated totals), Golden-Ledger-50 (end-to-end weeks, 100% fake-alert rejection, seeded gaming must trigger cases), vintage-as-eval-set (PD/late/default per tier × verified-share at 30/90/180d); weekly 2–5% auto-accept sampling, confidence-distribution plots, cohort reconciliation health, fraud/loss leading indicators, feed-staleness downgrades. Ship order: capture QA + quarantine → R1–R5 + tiered ledger → hedged advice → gated referrals, each before the next.
